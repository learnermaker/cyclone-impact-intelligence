# Data Preparation Guide

## Overview

The primary demo uses a **synthetic demo fixture** (`data/fixtures/fani-demo/`) generated by `pnpm generate:fixture`. This enables offline operation without any external data dependencies.

For a stronger submission, replace the synthetic fixture with real derived data from the pipelines below.

## Synthetic Demo Fixture

Generated by: `pipelines/fani/generate-demo-fixture.ts`

| File | Description | Status |
|---|---|---|
| `cells.geojson` | 43,009 H3 res-8 cells with synthetic hazard/exposure/susceptibility | Generated |
| `hazard_scenario.json` | T-24h HazardScenario based on IMD documented parameters | Pre-written |
| `infrastructure.json` | 15 curated infrastructure locations (approximate coordinates) | Pre-written |
| `metadata.json` | DemoFixtureMetadata with DEMO_FIXTURE tag and evaluation warning | Pre-written |

**Label**: All synthetic fixture files carry `dataStatus: "DEMO_FIXTURE"` and must never be used to claim historical Fani accuracy metrics (enforced by Zod schema at runtime).

### Step 2: NASADEM Elevation

### Step 3: OSM January 2019 Infrastructure

**Source**: Geofabrik India January 2019 extract
**Script**: `pipelines/osm/README.md`
**Output**: `data/processed/infrastructure_2019.geojson`

```bash
# Process with osmium (example):
osmium tags-filter india-2019.osm.pbf \
  amenity=hospital amenity=shelter \
  highway=primary highway=trunk \
  bridge=yes power=substation \
  -o odisha_infra.osm

osmium extract -b 83.5,17.5,87.5,22.0 odisha_infra.osm -o odisha_aoi.osm
```

### Step 4: GPM IMERG Fani Event Rainfall

**Script**: `pipelines/gee/04_gpm_imerg_fani.js`
**Output**: `data/processed/gpm_imerg_fani_48h.json`

### Step 5: Copernicus EMSR357 (Actual Evidence)

**Source**: https://mapping.emergency.copernicus.eu/activations/EMSR357/
**Script**: `pipelines/copernicus/README.md`
**Output**: `data/historical/fani/actual/copernicus_emsr357_inundation.geojson`

**CRITICAL**: This goes under `data/historical/fani/actual/` — NOT under `prediction/`.
The information firewall enforces separation at runtime.

## Replacing the Synthetic Fixture

Once real data is available:

1. Replace `data/fixtures/fani-demo/cells.geojson` with real derived cells
2. Replace `data/fixtures/fani-demo/infrastructure.json` with OSM extract
3. Update `data/fixtures/fani-demo/metadata.json`:
   - Change `dataStatus` to `"REAL_DATA"` or `"MIXED"`
   - Change `synthetic` to `false`
4. Run `pnpm test` — fixture contract tests will validate the new data

The engine contracts (TypeScript types + Zod schemas) do not change between synthetic and real data.
